what it is

One config.yaml  →  two containers.

🤖 agent

Untrusted · non-root · network-isolated · holds zero secrets.

the box

🛡️ gateway

Trusted · holds all secrets · the only way out.

the wall

Isolation is structural, not "we trust it to behave." The agent physically cannot read a secret — secrets never enter its container.

It isn't a rule the agent could talk its way around — it physically can't reach your keys.

The trust boundary is the network itself, not a setting — the agent has no path to the internet, and the gateway is the only bridge out. Default is deny if no hosts whitelisted; the real key is revealed at one place — the socket write, inside the door. Fail-closed everywhere.

09
the honest boundary · threat model
✓ What this stops
  • Agent reading a secret — keys never enter its container
  • Key exfiltration — agent has no route to the internet
  • Rogue egress — default-deny; only hosts you allow
  • Prompt-talking its way past a rule — the boundary is the network, not a setting
! What it does not (yet)
  • Secret-at-rest: the gateway holds .env in plaintext — a host-read threat, not an agent one
  • A compromised gateway = game over (it holds the keys by design)
  • CLI supply chain — trust is builtin:// / local://, both code-reviewed
  • Docker-only cap posture verified; podman + read-only rootfs pending

The core guarantee is structural agent isolation. The rest is defense-in-depth we're honest about — all tracked in docs/architecture/known-debt.md.

how to set it up
# 1 · scaffold config via an interactive wizard
agent-sandbox init

# 2 · provide secrets: copy the example and fill it in
cp .agent-sandbox/.env.example .env && $EDITOR .env

# 3 · review the generated config
$EDITOR .agent-sandbox/config.yaml

# 4 · generate artifacts, build & start the sandbox
agent-sandbox run up

# 5 · use the container shell
agent-sandbox run shell

14
it's not perfect yet

Some limits are the price of the isolation. Some just aren't done yet.

◧ By design — the price of isolation
  • No sharing a host folder. It would punch a hole in the isolation, so the checks reject it — edit inside the box (git, VS Code, code-server, file view).
  • Apps that need a screen. The usual display wiring is exactly what the checks refuse — planned fix: a desktop inside the box over a controlled connection.
  • Secret-at-rest on the gateway is plaintext. A host-read threat, not an agent one — encryption is a separate key-management decision.
◫ Not done yet — on the roadmap
  • Pillar 1 (verify + visualize) — direction only, no code yet.
  • Docker inside the box. Worked in v1; v2 mostly ported, not fully wired/tested.
  • Smoother agent login for some tools; read-only rootfs + podman cap-posture.
  • Install needs payfazz org access + a one-time classic PAT; pre-1.0, a minor bump may break.

Naming the limits plainly is what makes the hard claims credible. We want your feedback and your contributions.
